# 第六轮：PostgreSQL 持久化与领域事务

## 统一数据仓库

页面和 Route Handler 不再直接操作进程内数组。`lib/repositories/` 按账户、机会、组队和社区拆分数据访问；配置 PostgreSQL 时使用 Prisma，无数据库时使用同一接口的内存演示实现。

这层边界使 UI 和业务接口不需要知道数据来自哪里，也为后续测试、缓存和独立服务拆分保留了稳定入口。

## 组队一致性

组队的关键规则同时由领域校验和数据库约束保证：

- 一个用户在同一比赛只能属于一个队伍。
- 一个队长在同一比赛只能发布一条招募。
- 同一用户不能重复申请同一队伍。
- 审批通过、成员写入、队伍人数更新和通知在同一事务中完成。
- 删除队伍通过级联关系清理成员、申请和邀请。

并发冲突会转换为可理解的 409 业务响应，不把数据库错误直接暴露给前端。

## 初始化与运行状态

初始迁移位于 `prisma/migrations/20260825000000_init`，`prisma/seed.ts` 提供可重复执行的演示数据。新增 `/api/health` 用于识别当前数据后端、数据库连通性和 AI 配置状态。

没有数据库时，项目仍可在 `memory` 模式完整演示；切换到 PostgreSQL 后，账户画像、赛事、组队、文章与通知会在重启后保留。
