# 第三轮：意向驱动的双向组队

## 入口分流

- `/opportunities/[id]/recruit`：面向队长，创建队伍、查看意向候选人、打开用户主页并发送邀请。
- `/opportunities/[id]/teams`：面向队员，只展示未截止且仍有名额的招募队伍。
- `/opportunities/[id]`：角色选择页，解释两个入口的差异。

## 标准化画像

画像由 12 道统一的 5 级量表题生成，分别计算技术实践、创意表达、团队协作和探索执行。评分公式固定，避免自由文本长度和表达能力直接影响能力分数。问卷不是心理诊断，也不输出固定人格标签。

## 两阶段推荐

```text
候选用户
  └─ 第一阶段：是否标记本场比赛参赛意向
       └─ 第二阶段：比赛标签 × 用户能力画像排序
```

没有表达本场意向的用户不会进入队长推荐名单。用户可在报名开始前、报名期间或报名结束后标记意向，因为意向代表参与偏好，不等于官方报名。

## 招募有效性

队伍字段包括队伍名称、可选项目方向、队长联系方式、可选介绍、招募要求、人数上限、已有成员及招募截止日期。接口只返回未超过截止日期且仍有空位的队伍。

## 邀请链路

队长点击推荐用户头像后查看主页、联系方式与可投入时间。创建本场队伍后可发送邀请；重复的待处理邀请会被服务端拒绝。邀请记录可在申请管理页查看。
