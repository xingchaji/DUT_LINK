# 第二轮功能重构

本轮目标：把机会中心从“比赛列表”重构为“围绕每场比赛完成组队”。

## 页面结构

- `/opportunities`：比赛总览、画像推荐、校内比赛发布。
- `/opportunities/[id]`：比赛信息、本场招募队伍、发布招募、本场推荐队友。
- `/applications`：申请人查看状态，队长接受或拒绝申请。
- `/teams`：兼容旧链接，自动跳转到机会中心。

## 排序规则

比赛总览按 `registrationStart` 升序。缺少报名开始日期的官方赛事排在已知日期之后，界面显示“待补充”，不由模型猜测。

推荐比赛根据画像中的技能、兴趣、潜在方向与比赛标签计算，推荐结果不修改赛事事实。

## 校内发布

登录用户可以代表校内组织发布比赛。首发状态为 `pending`，页面显示“待核验”；用户发布活动不默认声明综测加分，也不作为官方选手报名系统。

## 申请状态机

```text
pending ──接受──> accepted（队伍人数 +1）
   └────拒绝──> rejected
```

重复处理、重复申请、申请自己的队伍和满员队伍都会被服务端拒绝。
