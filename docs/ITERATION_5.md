# 第五轮：统一用户资料与需求驱动推荐

## 统一个人主页

`/account` 现在同时展示和编辑账户公开资料、技能标签、兴趣、竞赛能力画像与潜在方向。`/profile` 仅作为兼容入口跳转到 `/account`，导航不再出现两个用户入口。

个人技能和建队技能共享 `TagEditor`：按 Enter 创建标签，点击标签删除；服务端继续执行去空、数量和长度限制。

## 可追溯的队伍成员

内存领域模型不再保存成员姓名字符串，而是保存带 `userId` 的成员摘要。队员通过申请后，系统从统一用户资料目录生成成员记录；用户更新公开资料时，所有队伍中的对应摘要同步更新。

招募卡和队长工作台中的成员姓名均链接到 `/people/[id]`。鼠标悬浮或键盘聚焦时显示昵称、专业、年级和技能标签，点击后进入公开主页。

## 队伍需求驱动推荐

```text
队长填写招募技能 + 具体要求
  → 创建队伍
  → 参赛意向优先筛选
  → 候选人能力画像 × 技能标签 × 招募要求排序
  → 显示每位候选人的具体命中理由
```

推荐接口为 `GET /api/recruitments/[id]/recommendations`，只允许队长访问本队推荐。配置兼容 Chat Completions 的模型时返回 AI 结构化排序；未配置或调用失败时使用本地可解释规则；需求不足时返回 `profile-fallback` 状态。

## 跨专业能力调查

16 题结构保持统一可比，前八题移除编程、机器学习、调试和 UI 工具等专业限定，改为问题解决与调研表达两组跨专业能力。后八题继续记录参赛层级、角色、答辩、协作、成果和投入时间。

## AI 三模块接入

- 能力画像：固定公式计算四维分数，AI 根据原始答案解释证据并生成潜在方向，不允许修改分数。
- 智能组队：AI 接收比赛、队伍需求和候选人画像，只能返回候选人 ID、匹配度与理由。
- 探索盲盒：AI 根据用户公开资料生成跨域连接，但引用只能来自服务端可信来源目录。
- 三项能力均使用 20 秒超时、JSON 输出校验和本地降级；`GET /api/profile` 可查看当前 AI 配置状态和能力清单。
