# 第四轮：账户资料与队伍一致性

## 个人主页

`/account` 与 `/api/account` 独立管理账户公开资料，包括昵称、专业、年级、联系方式、简介和技能标签。能力画像仍是独立的竞赛能力调查结果，避免把账户展示资料和匹配评分混为一体。

## 同比赛单队规则

```text
同一 user + opportunity
  └─ 只能对应一个 competition membership
       ├─ captain：该场比赛只能发布一个 RecruitmentPost
       └─ member：只能存在于一个已接受申请对应的队伍
```

创建队伍、申请加入和队长接受申请三个入口都会重新校验，防止并发或绕过前端。正式 PostgreSQL 模型使用唯一约束作为最终一致性保障。

## 成员与删除

- 建队时成员只有队长，不提供“已有成员”手工输入。
- 队长接受申请后，申请人自动进入成员名单。
- 删除队伍需要二次确认，同时删除该队伍的申请和邀请；删除后成员可以加入本场其他队伍。

## 技能标签

技能输入使用 tag editor：输入文字后按回车生成标签，可继续添加或点击标签删除，最多保存 8 项。服务端仍执行去空、截断和数量限制。

## 竞赛能力调查 v2

题目由 12 道性格倾向量表改为 16 道经验与能力分档题，覆盖：

- 编程、AI、调试、原型实现；
- 视觉表达、答辩、调研、项目书写作；
- 参赛次数、最高奖项、最高角色、正式答辩次数；
- 已交付项目、多人协作、可验证成果、稳定投入时间。
