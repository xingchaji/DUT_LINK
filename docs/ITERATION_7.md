# 第七轮：数据库认证与邀请回应闭环

## 数据库账号与会话

PostgreSQL 模式不再把用户资料写进 Cookie。注册或登录成功后，服务端生成高强度随机令牌；浏览器通过 HttpOnly Cookie 保存原始令牌，数据库只保存 SHA-256 哈希和过期时间。退出时同步删除数据库会话。

密码使用 Node.js `scrypt` 独立加盐哈希，并通过恒定时间比较验证。注册接口在服务端限制大连理工大学邮箱域名、密码长度和字母数字组合。当前只是校园邮箱域名准入，邮箱所有权验证码需要后续邮件服务支持。

内存模式仍保留原签名 Demo 会话，确保没有数据库时可以演示，但注册功能只在 PostgreSQL 模式开放。

## 邀请处理闭环

申请中心现在包含四个列表：收到的申请、发出的申请、收到的邀请和发出的邀请。被邀请人可以接受或拒绝；发起人只能查看结果。

接受邀请时，下列操作在同一串行化事务中完成：

1. 校验邀请归属、待处理状态、截止日期和队伍容量。
2. 校验用户未加入本场比赛的其他队伍。
3. 创建比赛成员关系并更新队伍人数。
4. 接受当前邀请，关闭同场其他待处理申请与邀请。
5. 给队长创建处理结果通知。

数据库唯一约束作为并发场景的最后防线，冲突会转换为 409 业务响应。
