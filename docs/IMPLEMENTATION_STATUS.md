# 问题清单实施状态

更新日期：2026-08-26（第九轮）

## 1. 能力画像

已完成第二阶段：

- 录入项目经历、获奖、可验证成果和 GitHub 仓库说明。
- 每项能力带分数、置信度和证据，不再只有装饰性进度条。
- 配置 AI 后使用结构化模型分析；无密钥或模型失败时降级到规则分析。
- 新画像同步保存到服务端数据仓库，并直接参与人员匹配与机会排序；浏览器缓存只用于兼容旧数据。
- 主画像入口已改为 12 道统一 5 级量表，使用固定公式计算四个能力维度，减少自由文本表达差异。
- 第四轮升级为 16 道竞赛能力调查，增加参赛次数、最高奖项、队伍角色、答辩次数和项目交付记录，删除大部分性格倾向题。
- 第五轮将前八题改成任务拆解、资料核验、证据分析、工具学习、需求定义、调研、写作和答辩等跨专业能力，并将画像合并进统一个人主页。
- 标准化问卷现已接入 AI 解释：固定公式保留评分权，模型只生成总结、潜在方向和维度解释，非法输出自动回退。
- 第九轮删除问卷中的称呼、专业和年级输入；页面展示个人主页同步结果，服务端以当前登录用户资料为唯一身份来源。

下一阶段：通过 GitHub OAuth 同步公开仓库指标，建立画像历史版本和用户确认机制。

## 2. 值得认识的人

已完成第一阶段：

- 匹配分解为技能互补 50%、兴趣桥接 30%、跨专业价值 20%。
- 页面显示每个维度的分数和推荐依据。
- 用户更新画像后会重新计算。

下一阶段：加入可用时间、合作方式、隐私范围、负反馈和双向意愿。

## 3. 机会与招募

已完成第一阶段：

- 机会中心提升为首页主板块。
- 默认目录替换为带官方来源和核验时间的真实赛事。
- AI/算法只排序可信目录，不允许生成不存在的赛事事实。
- 每项赛事单独展示综测政策；未录入学院文件时明确显示“待导入”。
- 支持发布招募、浏览招募和报名，写操作要求登录。
- 比赛总览与推荐比赛已经拆分，总览按报名开始时间排序，缺失日期不会由 AI 猜测。
- 招募队伍按比赛聚合，每场比赛拥有独立详情与组队空间。
- 支持用户和校内组织发布歌唱、体育、学术、创新创业等校内比赛。
- 首页和机会中心的产品重心调整为“寻找队友”，不承担官方选手名单统计。
- 申请加入会生成可追踪记录；队长可以接受或拒绝，接受后队伍人数自动更新。
- 原智能组队入口合并到比赛详情，根据不同比赛标签重新推荐用户。
- 队长招募工作台与队员找队页已拆成独立路由和界面。
- 用户可跨报名周期标记比赛意向；队友推荐先按比赛意向过滤，再按画像排序。
- 推荐用户头像可打开用户主页，展示联系方式并发送组队邀请。
- 队伍信息补齐方向、联系方式、介绍、要求、已有成员和截止日期，过期或满员招募自动隐藏。
- 建队时不再手填已有成员，审批通过后自动更新成员名单。
- 同比赛单用户单队、队长单招募规则由服务端校验，并在 Prisma 中准备唯一约束。
- 队长可以二次确认后删除队伍，关联申请和邀请同步清理。
- 招募技能支持输入后按回车生成多个标签。
- 队伍成员改为稳定用户实体；成员姓名可点击进入公开主页，悬浮或键盘聚焦可查看昵称、专业、年级和技能标签。
- 智能推荐只在队长补全并创建队伍后展示，综合参赛意向、候选人画像、队伍技能标签和招募要求，并逐人显示命中理由。
- AI 服务未配置或失败时保留可解释规则结果；招募信息不足时明确回退到参赛意向与能力画像匹配。
- 产品入口已由“机会中心”统一命名为“组队中心”。
- 智能推荐候选池已改为读取数据库用户、参赛意向和能力画像，并排除队长及本队成员；模型输入明确包含画像技能证据、兴趣、队伍标签与招募要求。

第六轮完成 PostgreSQL/Prisma 持久化：赛事、意向、招募、成员、申请、邀请和通知已迁移到统一仓库层；关键组队写操作使用事务及唯一约束。

下一阶段：邀请接受/拒绝闭环、校内发布审核后台、定时采集、来源变更检测与学院综测文件导入。

## 4. 知识盲盒

已完成第一阶段：

- 可以随机切换跨领域主题。
- 显示推荐原因与论文/文章来源。
- 支持学生投稿跨领域文章，文章可成为人与人连接的入口。
- 探索盲盒已接入 AI 个性化生成；模型只能选择可信来源目录中的 source ID，服务端负责回填真实链接，失败时返回人工策划内容。
- “获奖作品专业解读”已升级为画像驱动：结合个人专业、公开技能及能力画像，对创新大赛、挑战杯和计算机设计大赛的官方获奖作品进行相关性排序；文章被拆分成可点击的小板块，每个板块可继续展开作品设计思路、其他领域知识的具体使用位置、跨模块结合方式、参赛行动清单、答辩证据、常见误区和原作品官方链接。作品事实由服务端锁定，即使 AI 不可用也会返回结构完整的人工核验内容。
- 组队中心官方竞赛目录由 3 项扩充到 10 项，新增数学建模、电子设计、网络技术、服务外包、机械创新、智能汽车和广告艺术赛事；仅录入官方来源可核验的日期，不确定日期不做推测。
- 探索页收拢为“跨域灵感”和“获奖作品解读”两个同级主板块。灵感来源、同学文章、联系人和投稿不再分散成独立卡片；推荐同学卡片可直接打开公开主页查看联系方式。

下一阶段：内容审核、个性化探索 Agent、阅读反馈和作者私信。

## 5. 登录与会话

第七轮完成数据库认证基础：

- PostgreSQL 模式使用 scrypt 加盐密码哈希。
- 登录和注册成功后创建随机会话令牌，数据库只保存 SHA-256 令牌哈希。
- 退出登录会删除数据库会话，Cookie 使用 HttpOnly、SameSite=Lax，生产环境启用 Secure。
- 注册限制大连理工大学邮箱域名，服务端校验昵称、专业和密码强度。
- 内存模式继续提供签名 Demo 会话，保证零数据库演示。
- 内存模式支持本次运行有效的临时校园账号注册，并提供两个学生演示账号用于双浏览器组队验收。
- 页面使用 Proxy 做乐观重定向，写 API 和数据访问层执行真实会话及权限校验。
- 账户公开资料与能力画像已经支持 PostgreSQL 持久化。

当前 Demo 种子账号仅用于功能验证。生产版本仍需校园邮箱验证码、找回密码、登录限流、会话设备管理和异常登录风控。

第五轮统一个人主页：登录用户可以在同一页维护昵称、专业、年级、公开联系方式、个人介绍、Enter 技能标签并查看竞赛能力画像；资料更新会同步导航身份、队长名称和队伍成员摘要。

第八轮增加用户级 AI 设置：个人主页可统一启停问卷画像、智能组队和探索盲盒，配置兼容 Chat Completions 的 API Key、根地址与模型；密钥使用 AES-256-GCM 服务端加密，读取接口不返回明文，关闭时三项能力统一使用本地降级方案。

## 6. 组队邀请回应

第七轮完成：

- 申请中心同时展示收到/发出的申请与邀请。
- 被邀请人可以接受或拒绝邀请，其他用户不能越权处理。
- 接受邀请、写入比赛成员、更新队伍人数、更新邀请状态和通知队长在同一串行化事务中完成。
- 用户加入一支队伍后，同场比赛的其他待处理申请与邀请自动关闭，数据库唯一约束继续保证单比赛单队。
