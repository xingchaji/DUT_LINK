# 问题清单实施状态

更新日期：2026-08-20

## 1. 能力画像

已完成第一阶段：

- 录入项目经历、获奖、可验证成果和 GitHub 仓库说明。
- 每项能力带分数、置信度和证据，不再只有装饰性进度条。
- 配置 AI 后使用结构化模型分析；无密钥或模型失败时降级到规则分析。
- 新画像保存在浏览器中，并直接参与人员匹配与机会排序。

下一阶段：通过 GitHub OAuth 同步公开仓库指标，把画像和版本存入 PostgreSQL。

## 2. 值得认识的人

已完成第一阶段：

- 匹配分解为技能互补 50%、兴趣桥接 30%、跨专业价值 20%。
- 页面显示每个维度的分数和推荐依据。
- 用户更新画像后会重新计算。

下一阶段：加入可用时间、合作方式、隐私范围、负反馈和双向意愿。

## 3. 机会与招募

已完成第一阶段：

- 机会中心提升为首页主板块。
- 默认目录替换为带官方来源和核验时间的真实赛事。
- AI/算法只排序可信目录，不允许生成不存在的赛事事实。
- 每项赛事单独展示综测政策；未录入学院文件时明确显示“待导入”。
- 支持发布招募、浏览招募和报名，写操作要求登录。
- 比赛总览与推荐比赛已经拆分，总览按报名开始时间排序，缺失日期不会由 AI 猜测。
- 招募队伍按比赛聚合，每场比赛拥有独立详情与组队空间。
- 支持用户和校内组织发布歌唱、体育、学术、创新创业等校内比赛。
- 首页和机会中心的产品重心调整为“寻找队友”，不承担官方选手名单统计。
- 申请加入会生成可追踪记录；队长可以接受或拒绝，接受后队伍人数自动更新。
- 原智能组队入口合并到比赛详情，根据不同比赛标签重新推荐用户。

下一阶段：PostgreSQL 持久化、校内发布审核后台、定时采集、来源变更检测与学院综测文件导入。

## 4. 知识盲盒

已完成第一阶段：

- 可以随机切换跨领域主题。
- 显示推荐原因与论文/文章来源。
- 支持学生投稿跨领域文章，文章可成为人与人连接的入口。

下一阶段：内容审核、个性化探索 Agent、阅读反馈和作者私信。

## 5. 登录

已完成 Demo 会话：

- 服务端验证账号。
- HMAC 签名、HttpOnly、SameSite Cookie。
- 页面使用 Proxy 做乐观重定向，写 API 再做真实会话校验。

当前固定 Demo 账号仅用于功能验证。生产版本仍需数据库密码哈希、校园邮箱验证、找回密码、风控和 Auth.js。
